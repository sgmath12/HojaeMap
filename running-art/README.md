# 러닝 아트 — 분당

성남시 분당구(정자·서현·수내·야탑과 탄천·중앙공원)에서 **달리면 그림이 되는 코스**를 찾아주는 도구입니다.

내가 모양을 그려 넣는 방식이 아니라, **이미 있는 도로 중에서 그 모양이 나오는
자리를 찾아내는** 방식입니다. 그래서 "이 동네에서 뭘 그릴 수 있나"에 답이 나옵니다.

## 실행

`file://`로 열면 `fetch()`가 CORS에 막혀 코스가 안 뜹니다. 반드시:

```bash
cd running-art
python3 -m http.server 8124   # → http://localhost:8124/
```

## 줌 단계로 보이는 게 바뀝니다

호재맵과 같은 방식입니다. 한 화면에 다 밀어 넣지 않고 줌으로 나눕니다.

| 줌 | 보이는 것 |
|---|---|
| ~12 | **모양 보기.** 지역 위에 모양 윤곽만 색깔별로 뜹니다 |
| 14~15 | **코스 보기.** 선택한 모양의 실제 도로 경로가 겹쳐 나옵니다. 점선이 원래 모양 |
| 16~ | 위에 더해 **1km 지점 표시** |

모양이 서로 겹쳐 보이는 건 정상입니다 — 길이 잘 연결된 구역으로 후보가 몰리기
때문입니다. **클릭하면 그것만 남고 나머지는 흐려집니다.** 겹치는 게 싫으면
사이드바의 "겹치지 않게 한 벌만 보기"를 켜세요 (`poster` 플래그, 정자역은 5개가
서로 안 겹치게 들어갑니다).

## 파일

| 파일 | 설명 |
|---|---|
| `index.html` | 뷰어. 작업은 이 파일에 합니다. Leaflet CDN, 빌드 없음 |
| `preview.png` | 상위 코스 미리보기 (문서용) |
| `tools/region.py` | **대상 지역 설정. 지역을 바꾸려면 여기만 고칩니다** |
| `tools/fetch-osm.py` | Overpass에서 보행 가능 도로망 수집 → `data/osm-raw.json` |
| `tools/fetch-extra.py` | 신호등·횡단보도 → `data/osm-nodes.json` |
| `tools/fetch-elev.py` | 고도(SRTM 30m) → `data/elev.json`. 중간에 끊겨도 이어받습니다 |
| `tools/fetch-places.py` | 공원·하천 → `data/osm-places.json` |
| `tools/graph.py` | 도로망 → 그래프. 좌표를 로컬 미터로 투영 |
| `tools/shapes.py` | 모양 템플릿 11개 |
| `tools/match.py` | **핵심.** 도로망에서 모양이 나올 자리 탐색 |
| `tools/build-courses.py` | 전체 탐색 → `data/courses.json` |

`data/*.json`은 **자동 생성 파일입니다. 직접 고치지 마세요.**

`courses.json`은 모양당 최대 4개(+포스터 배치)만 담습니다. 탐색은 모양당 14개까지
하되 자리를 600m 격자로 흩어 뽑습니다 — 안 그러면 한 구역에서 미세하게만 다른
후보가 목록을 다 채웁니다.

```bash
python3 tools/fetch-osm.py       # 도로망 (지역 바꿀 때만)
python3 tools/fetch-extra.py     # 신호등·횡단보도
python3 tools/fetch-places.py    # 공원·하천
python3 tools/fetch-elev.py      # 고도, 약 5분 (초당 1회 제한)
python3 tools/build-courses.py   # 코스 재생성 (약 50초)
```

## 어떻게 찾는가

1. 모양을 등간격 34점으로 나눕니다.
2. 지도 위 여러 **위치 × 크기 × 각도 × 좌우반전**에 그 34점을 놓아봅니다.
   (격자 180m, 반폭 350~1400m, 30°씩 12방향 → 배치 후보 5천여 개)
3. 34점이 전부 도로 근처(≤180m)에 떨어지는 배치만 남깁니다.
4. 남은 배치의 점 사이를 **실제 도로로 잇습니다.**
5. 원래 모양과 얼마나 닮았는지 + 달릴 만한지를 점수로 매깁니다.

### 4번이 그냥 최단경로면 안 됩니다

두 점 사이 최단경로를 쓰면 모양 안쪽을 가로질러 버려서 그림이 뭉갭니다.
그래서 **외곽선에서 멀어지는 간선에 벌점**을 매깁니다 (`OFF_K`). 이걸 넣기 전엔
닮음이 35점이었고 넣은 뒤 50점대로 올라갔습니다.

벌점을 곱한 비용과 기하 거리를 같은 자로 재면 안 됩니다 — 컷오프에 멀쩡한
경로가 전부 걸려서 결과가 통째로 비었던 적이 있습니다 (`OFF_CLIP` 참고).

### 되돌아 뛰는 건 벌점을 세게 주면 안 됩니다

별 뿔이나 하트 골처럼 뾰족한 데를 그리려면 **들어갔다 되나와야** 합니다.
GPS 아트에선 정상인데, 처음엔 되돌아오기에 벌점을 세게(1.6배) 줘서 알고리즘이
뾰족한 모양을 아예 포기하고 둥근 덩어리만 골랐습니다. 0.6으로 낮췄습니다.

## 러닝 코스로 쓸 만한가 (러닝 점수)

그림만 보고 고르면 계단 범벅에 신호 대기 잦은 코스가 1등이 됩니다. 그래서
**닮음과 러닝을 곱해서** 최종 순위를 냅니다.

```
종합 = 닮음^0.65 × 러닝^0.35
```

곱셈인 이유는 한쪽이 0에 가까우면 코스로 못 쓰기 때문입니다. 가중합으로 하면
그림이 아주 잘 나오는 계단 코스가 위로 올라옵니다.

러닝 점수는 100에서 **뛰다 멈추게 하는 것**을 깎습니다.

| 항목 | 깎는 양 | 출처 |
|---|---|---|
| 오르막 | km당 10m 초과분 × 1.6 | SRTM 30m (`data/elev.json`) |
| 신호 대기 | km당 개수 × 6 | OSM `traffic_signals` (횡단보도는 0.35로 셈) |
| 계단 | 1m당 0.05 | OSM `highway=steps` |
| 큰길 비중 | 비율 × 45 | OSM `tertiary`·`secondary` |
| 되돌아오기 | 비율 × 40 | 같은 간선 재통과 |
| 거리 | 5~10km 밖으로 벗어난 만큼 | — |
| **탄천·공원길** | **비율 × 20 만큼 더해줌** | 공원 폴리곤·하천 120m |

### 누적 오르막은 반드시 평활한 뒤에 더하세요

SRTM 30m는 수직 오차가 ±5~10m입니다. 25m 간격 노드마다 고도차를 그대로 더하면
**없는 오르막이 쌓입니다.** 실제로 고저차 53m인 코스가 285m로 나왔습니다(5.4배).
100m로 재샘플하고 500m 창으로 평활하면 59m — 언덕 한 번 오르내린 값과 맞습니다.
`climb_of()`를 고칠 일이 있으면 이걸 먼저 확인하세요.

### 정자동은 러닝 점수가 다 높습니다 (70~93)

평지에 큰길이 적고 보행로가 많아서입니다. **점수 폭이 좁다고 억지로 늘리지
마세요.** 실제로 뛰기 좋은 동네인 게 맞습니다. 깎인 것들은 이유가 분명합니다 —
별은 되돌아오기 44%, 고래는 계단 148m.

## 정자동에서 실제로 나오는 것 / 안 나오는 것

계획도시라 블록이 커서 **도로가 촘촘하지 않습니다.** 오목한 디테일을 만들 길이
없어서 모양을 가립니다.

- 잘 나옴: 나뭇잎, 물방울, 고양이, 돌고래, 하트
- 안 나옴: **별** — 뿔 사이 홈을 그릴 길이 없어 둥근 덩어리가 됩니다.
  거북이도 다리가 뭉개져 덩어리로 보입니다.

**닮음 55점이면 꽤 잘 나온 겁니다.** 도로 위에서는 60을 넘기 어렵습니다.
점수를 올리고 싶다고 지표를 손보지 말고, 안 나오는 모양은 안 나온다고 두세요.

## 사람들이 실제로 뛰는 길 (탄천·중앙공원)

처음 판은 코스가 전부 주택가 이면도로로 나왔습니다. 중앙공원 이용률이 0~17%.
격자형 골목이 모양 맞추기에 유리해서 탐색이 그쪽만 골랐던 겁니다.

`data/osm-places.json`에 공원 경계와 하천 선을 받아 **공원 안 / 하천 120m 안**
노드를 표시합니다. 길 종류(footway)로는 구분이 안 됩니다 — 아파트 단지 보도도
footway라서요. 녹지 647개 중 대부분이 1ha 미만 단지 조경이라 **1ha 이상만,
grass는 빼고** 셉니다. 검증: 중앙공원 폴리곤 안 노드 100% 판정, 하천변 노드
평균 고도 47m(전체 68m).

### 라우팅 할인으로 끌어오면 안 됩니다

공원길 라우팅 비용을 0.8배로 깎아봤더니 경로가 외곽선에서 끌려나가
**나뭇잎 닮음이 55.7 → 46.3으로 무너졌습니다.** `SCENIC_PREF`는 1.0으로 두세요.
선호는 "어디에 놓을지"(배치 후보)에서만 겁니다.

### 그림과 산책로는 실제로 상충합니다

탄천은 선형이고 중앙공원은 곡선 루프라 격자보다 모양이 안 나옵니다. 한쪽으로
밀면 다른 쪽이 죽습니다. 그래서 **탐색 예산을 반씩 나눠** 일반 코스와 공원·하천
코스를 따로 뽑고, 결과도 따로 남깁니다(`KEEP_SCENIC`). UI에서 "탄천·공원길
위주만 보기"로 갈라 봅니다.

닮음은 대체로 5~10점 낮습니다. 이건 억지로 못 메웁니다 — 대신 러닝 점수가
높습니다(탄천 초승달 코스는 러닝 100점).

## 탐색 예산은 크기별로 똑같이 나눕니다

스냅 거리를 **절대 미터로 재면 작은 배치가, 모양 크기로 나누면 큰 배치가**
상위를 독식합니다. 260m 스케일을 넣었을 때 나뭇잎 닮음이 55.7 → 35.8로
떨어진 게 이 때문이었습니다. 크기마다 같은 수만큼 경로 계산을 태웁니다.

`ROUTE_TOP`은 지역 넓이에 비례해야 합니다. 반경 5km에서는 2400에서 포화됩니다
(4000으로 올려도 상위 결과가 같습니다). 전체 재생성에 약 7분 걸립니다.

## 알려진 한계

닮음 점수는 **외곽선에서 얼마나 벗어났나**만 봅니다. 지느러미·꼬리처럼
모양을 알아보게 하는 특징이 뭉개져도 점수가 잘 나올 수 있습니다. 실제로
돌고래(닮음 54.6)와 고래(55.7)는 눈으로 보면 덩어리에 가깝습니다.
**점수만 믿지 말고 `preview.png`로 한 번 보세요.**

## 지역 바꾸기

**`tools/region.py` 한 곳만 고치면 됩니다** (`CENTER`·`RADIUS`·`SEARCH_R`·거리 범위).
그다음 수집 스크립트를 차례로 돌리세요. 도로가 촘촘한 구도심(격자형 골목)이
계획도시보다 훨씬 잘 나옵니다.

## 알아둘 것

- Overpass 본서버는 504를 자주 뱉습니다. `fetch-extra.py`처럼 미러를 돌아가며
  재시도하세요.
- Overpass API는 호출 제한이 있습니다. 도로망은 한 번 받아 `data/osm-raw.json`에
  두고 재사용하세요.
- 코스는 **추천일 뿐 안전을 보장하지 않습니다.** 횡단보도·신호·차도 여부를
  자동으로 다 거르지 못합니다. GPX를 받아 달리기 전에 한 번 눈으로 보세요.
- `COMFORT` 표로 차도에 가중치를 줘서 피하게 하지만, 완전히 배제하지는 않습니다.
